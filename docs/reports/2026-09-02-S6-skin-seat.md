# S6 — Moog / 2077 skin seat

Opened 2026-09-02. Status: pre-build.

## Findings that change the spec

**§9.3 is wrong.** It lists the piano roll, keyboard, and step grid as
unreachable by a skin. They are not.

- `keyboard.js` — 13 hex, all of them fallbacks inside `var()`. 4 locals are
  aliases (`--kbd-line: var(--line, #3a485f)`).
- `step-grid.js` — 7 hex, all fallbacks. 7 locals, all aliases.
- `piano-roll.js` — 0 hex, 207 `var()`. `--row-deg` / `--note-deg` set from JS
  to `var(--deg-*)`, so they ride the S4 palette already.

Colour on all three playing surfaces is fully skinnable today. The real gap is
geometry: 9 px literals across `piano-roll.js`, `step-grid.js`, `shell.js`.

**Devbox self-discovers.** `devbox.js` reads `:root` from `tokens.css` via
CSSOM (fallback: fetch + parse) and generates a control per token, typed by
shape. The knobs are not hand-authored. 348 tokens: 94 hex, 32 px/ms/rem,
73 `calc()` derived, 68 keyword.

**The two required toggles already exist.** `devbox.js:314` `animsOff`,
`devbox.js:324` `interactionsOff`.

**No skin loading exists.** `src/ui/skins/` holds only `_template.skin.css`.
No page carries a skin `<link>`. No switcher, no query param, no manifest.
The spec describes the mechanism; nothing implements it.
